SIMILE (web) - RELEASE NOTES
============================

Oldest first. The release you are running is shown at the right of the
menu bar. Each release is a date.

The site was first published on 8 August 2026, straight from the
development branch, without separate releases; the first release below
covers everything from then until 13 October 2026.


------------------------------------------------------------------------
Release 2026-10-13
------------------------------------------------------------------------

Running models
- Models run on the Simile engine, with a run control, a plotter of
  variables against time, and a spatial grid.
- Models with submodels and associations run too.
- Simile .pl model files can be imported, and a set of built-in models
  is listed under File > Models.

Building models
- A node properties dialog, with an Equation tab, a tree of Simile's
  functions, and clear messages when an equation is wrong.
- The alarm element is shown, greyed out until it is supported.
  Submodels can have more than one dimension.
- Elements are drawn smaller (70%), with text at the same size.
- Dragging a newly placed element keeps the name you were typing, as
  Enter does.

Windows and files
- Each model opens in its own Model window and Simulation window, with
  titlebars coloured by model. Panels inside a window have a quiet grey
  titlebar.
- View > Windows and Arrange windows are new. Closing a model's window
  closes its simulation window too.
- The current model is shown in the menu bar.
- Each panel is titled with a number, such as diagram/1.
- A small panel shrinks to a thumbnail of its picture.
- File > Export all backs up every model to one file.
- Session > Open as a new user shows the first-run screen in a new tab.
- A clicked window always comes to the front, and a reload keeps the
  order the windows were stacked in.

Touch screens
- Windows and diagrams can be dragged with a finger.

Release 2026-10-13b
------------------------------------------------------------------------

Tutorials
- Help > Tutorials has the first two of the old Simile tutorials,
  rewritten for the web version: Bank account and Predator-prey.

Building models
- Sketched graphs: a variable or flow has a Graph tab on its properties
  dialog, where a relationship can be drawn by hand and used in the
  equation as graph(x). Graphs in imported Simile models are kept.
- Influence arrows can be selected (they turn blue) and deleted.
- Names must be written with underscores, not spaces; the name box
  says so and suggests one.
- An influence from another submodel is shown with its path, such as
  /S1/a; one from the same submodel by its name alone.
- File > Rename model renames a model, and its windows follow.
- Renaming an element updates the equations that use it.
- The properties dialog's tabs and buttons stay in view while its
  contents scroll.

Running models
- A new time step is used from the next start of a run.
- Run after editing the model loads the edited model first.
- Run settings are remembered for each model.
- Models with capitalised names, or using time(), now run.

Windows and menus
- Choosing a window from View > Windows makes its model current.
- Menu separators are drawn as lines.

Release 2026-10-13c
------------------------------------------------------------------------

Tutorials
- Help > Tutorials > Trees, the third of the old Simile tutorials:
  modelling a population of trees as individuals.

Running models
- Widgets > Lollipop diagram shows the members of a population as
  lollipops standing on a gridded patch of ground: each at its x and y,
  as tall as its size. Turn and tilt the view with the sliders or by
  dragging; point at one to see its values.
- A plotter draws a variable in a population as one line for each
  member, from when it appears to when it goes.

Building models
- The population symbols are called creation, immigration and loss,
  as in Simile, and models using them can now be run.
- An immigration symbol asks for arrivals per time unit.
- An influence leaving a population is offered in the equation dialog
  as a list, such as {size}.

Release 2026-10-14
------------------------------------------------------------------------

Live models in your own web pages
- A Simile model can now be put into an ordinary web page, among your
  own text: its diagram, graphs of its results, a lollipop diagram,
  and sliders for its parameters. The model runs as the page opens;
  readers can move the sliders, or edit the model, and see what
  happens. Nothing they do is kept.
- Help > Live models in your own web pages explains how, step by step.
  A page needs one line to bring in Simile, and the model's script.
- File > Export model as script (.js) writes a model, with its run
  settings, as the script such a page loads.
- Two example pages: Rabbits and foxes (pages/predator-prey) and
  A stand of trees (pages/trees).

Building models
- A variable can have a Minimum and a Maximum. A variable with a
  number for its value, a minimum and a maximum, and nothing
  influencing it, is a parameter; Simile .pl files that give these
  keep them on import and export.

Running models
- Widgets > Sliders gives a slider for each of the model's parameters.
  Moving one runs the model again with that value, without changing
  the model; "model values" puts them back.
- A variable added since the model was loaded can be chosen for a plot
  straight away; it is plotted from the next run.
- Lengthening a run no longer makes it slower to fetch: the results
  come back in the same number of pieces whatever the run length.

Release 2026-10-16
------------------------------------------------------------------------

Models run in your browser
- Models now run in the browser itself, with no server: Simile's own
  tools turn the model into a program in the page, and it runs there.
  SimiLive is used only if that fails.
- The first run of a model in a visit takes several seconds while the
  tools load (about 39 MB the first time; the browser usually keeps
  them). After that a model is ready in about 3 seconds, and going
  back to a version already run is immediate. The page stays usable
  meanwhile; the status line says what it is doing.
- The app remembers the models it has prepared, so on your next visit
  an unchanged model runs at once.
- A run takes milliseconds rather than seconds. Sliders now re-run the
  model as you drag them, starting values included.

Live models in your own web pages
- The example pages come with their models ready to run, so they run
  as soon as the page opens, in the reader's browser. A page without
  that runs too, after preparing the model itself.
- Help > Live models in your own web pages says how this works.

Models
- File > Models has a new model: Pangolin harvest, converted from a
  published R model (Almeida et al., 2023).
- A number written with an exponent, such as 1.0e12, is now exported
  as written; before, the model would not run.

Release 2026-10-20
------------------------------------------------------------------------

Submodels
- A submodel can now be resized: drag any edge or corner (the pointer
  changes as you reach one). It will not shrink smaller than what it
  contains, nor grow outside the submodel around it or over anything
  else. One drag is one undo.
- Moving or resizing keeps a 10-unit gap from the edge of the submodel
  around it and from other submodels.
- A submodel's name now sits just above its top-left corner, rather
  than inside the box, and its corners are more rounded.

Population symbols
- Their property dialogs now say what each value means, following
  Simile's developer: creation is the number of members at the start;
  immigration the arrivals per time unit; reproduction the offspring
  per member per time unit; loss the probability of loss in one time
  unit (or a condition: removed when true).


------------------------------------------------------------------------
Release 2026-10-20b
------------------------------------------------------------------------

Associations
- An association joining two different submodels (eater and food, say)
  now exports and runs. Before, such a model was refused; the catalogue
  model feeding1 was the one example. Simile's developer explained how
  Simile numbers the roles, and the editor now does the same.

Time bases
- A submodel can now run on its own time base, with its own time step:
  the submodel's dialog has a "Time base" field (blank is the model's
  own). In an equation, dt(2) is the time step of time base 2.
- Simile models that use this (lamos1a, for example) are now imported
  with it, so they compile and run; before, they would not compile.
- A model with more than one time base has one time step per base in
  the run settings, for example "1 0.1". A base without one takes the
  last value given.


------------------------------------------------------------------------
Release 2026-10-21
------------------------------------------------------------------------

Associations
- A new role arrow is named after its submodel (farmer, and farmer2 for
  a second role from the same submodel), so the names an influence
  across the association brings read id_farmer rather than id_. A role
  arrow with no name is drawn red.
- A value coming out of an association into a submodel is a list, one
  value per pairing, and the property dialog now offers it that way:
  {variable1_farmer}. Writing it without the braces turns the equation
  red, with a message saying what to write.
- Roles that Simile marks as exclusive (each instance takes part at
  most once, as an ant is at one location) are kept on import, and a
  value through one is a single value. Some catalogue models that would
  not build from our copy before now do.
- Role arrows are thicker, with a bigger arrowhead, and curved; drag
  one to change its curve. Two between the same pair bend apart, each
  with its own label.

Drawing
- A flow can be drawn from empty space inside a submodel to a stock in
  it (or the other way): the cloud is made inside the submodel.
- A role arrow drawn from inside a submodel starts where you pressed.

Checks
- An equation that is a list as a whole is refused, as Simile refuses
  it: "The expression evaluates to a list. A model variable cannot
  represent a list" - with a suggestion such as sum({...}). Before, the
  model was accepted and then failed to compile.

Plots
- A submodel with a fixed number of instances (10 farmers, say) can be
  plotted: a line for each instance.
- A variable inside an association can be plotted: a line for each
  pairing, for as long as the pairing exists.

Submodels

Release 2026-10-25
------------------------------------------------------------------------

Widgets you add
- Widgets > Add a widget... adds a widget that is not built in: one you
  wrote, or someone else's, given by its address or by selecting the
  file. It joins the Widgets menu and opens for the current model as
  the built-in ones do. It is remembered next time.
- Widgets > Add a toolkit... adds several at once. Its list is shown
  first, and its widgets are loaded only if you agree.
- Widgets > Manage added widgets... lists them, with who wrote them, and
  reloads or removes them.
- Before anything is added you are told what an added widget can do:
  it runs inside the app, so add only widgets from people you trust.

Writing a widget
- Widgets > Instructions for an AI assistant... gives text to paste into
  a chat with an AI assistant, which then writes the widget for you.
- Help > Writing a widget is the guide for those who write their own.
- An error in an added widget is shown on its panel, with the file and
  line, and Reload runs the changed file again without closing the
  panel.

Release 2026-10-31b
------------------------------------------------------------------------

Submodels
- A satellite submodel (one with a single role arrow, so one instance
  for each instance of the submodel the arrow comes from) now counts as
  having many instances: a value leaving it is a list, written {name},
  as in Simile. The property dialog offers it that way.

Tables
- A table read from a data file in Simile (an equation using table(...))
  is now kept when a model is imported, and written back when it is
  exported, so such models compile and run. The property dialog has a
  Table tab showing where the values came from (file, column) and the
  values themselves. Reading the file again, or editing the values, is
  not possible yet.

Release 2026-11-01
------------------------------------------------------------------------

Parameters
- A variable's property dialog has a new choice, Data source, as in
  Simile: Derived (from its equation), Variable parameter (a slider, or
  values over time), or Fixed parameter (one value for the run). For a
  parameter the equation is optional: it is only a default.
- Widgets > Parameters opens a new panel listing every parameter of the
  model, grouped by submodel. Type a number, or several in brackets,
  [1, 2, 3]. A variable parameter can also be given values over time,
  {"0": 5, "10": 7}, with the run taking the last value, the closest
  value, or a value interpolated between the times. A change runs the
  model again from the start.
- The values are not part of the model. The panel remembers the ones
  you used last, and Save... and Load... keep sets of them in parameter
  files (.spf, in JSON), so one model can be run with several. Simile's
  own (XML) parameter files cannot be read yet.
- A model with a parameter that has no value will not run: the run
  control says which values are needed.
- Simile models with file parameters now import, export and run: 17 of
  the 20 catalogue models with parameters run in the page, including
  Thornthwaite. Parameters in a population, and values sent to a model
  running on SimiLive, are not done yet.

Import and export
- An equation written in Simile as if'Ta'>0 was imported as ifTa>0;
  fixed.
- A value such as "false" was exported in a form Simile could not read;
  fixed.

Release 2026-11-01b
------------------------------------------------------------------------

Values crossing submodel boundaries
- What an influence delivers when it comes out of submodels - a list,
  an array, a list of arrays, and so on to any depth - is now worked
  out by Simile's own rule, and the name is written in the matching
  brackets ({x}, [x], {[x]}, [[x]] ...). The property dialog inserts
  names that way, an equation that writes one differently is shown red
  with the exact form to use, and export writes what Simile writes.
  Checked against every such link in the catalogue and in a large
  model from Jasper: 4763 of 4783 agree, the rest being out of date in
  the files themselves.
- A role arrow may start at a submodel inside another one (a field
  inside a farm, say); such models now import and export correctly.
- One influence may cross two associations at once, giving a name for
  each role of each.
- An equation may use the same name in two forms, x and [x], when two
  influences supply them.

Import
- Very old Simile files (format 9.0) whose variables hold several
  values are read as arrays. Their equations sometimes use such a
  variable as if it were one value; those models now say so instead of
  exporting something that means something else.
- A submodel size given as size('name') follows the submodel when its
  name is changed on import.

Large models
- Jasper's nkometou model (99 submodels, over 5000 influences) now
  imports, exports, compiles in the page (it takes several minutes, once)
  and runs. Many of its values cannot be shown yet.

Release 2026-11-02
------------------------------------------------------------------------

Large diagrams
- Dragging no longer redraws the whole diagram at every movement: what
  is being dragged moves on its own, with only the arrows it pulls along
  redrawn, and the diagram is redrawn once when it is dropped. This
  holds for one element, several selected ones, a whole submodel, a
  name, a submodel being resized, a crossing point and an arrow being
  bent.
- Drawing is much faster: the nkometou model (99 submodels, over 5000
  influences) now opens in about two seconds instead of making the
  browser report the page as unresponsive, and a drop or an undo takes
  under half a second.
- Submodels can be drawn smaller than their contents, as in Simile: a
  submodel imported from Simile keeps the scale it had there, and its
  contents - symbols, arrows and names - are drawn at that size inside
  it, instead of spilling over its neighbours. Zoom in to read them;
  the view now zooms up to 60 times.

Import and export
- Exporting a model with submodels placed their contents in the wrong
  position when the file was opened in Simile; fixed. Positions are now
  checked when models are converted there and back.

Running models
- Values of every shape can be read from a model running in the page:
  lists of arrays, values per pairing, a conditional submodel's value
  or nothing.
- The Parameters panel reads Simile's own parameter files (.spf), as
  well as its own (now saved as <model>.parameters.json).
- A variable parameter with no value but a range runs at the middle of
  its range, and a true/false one with neither runs as false. These are
  stop-gaps, to be revisited.

Release 2026-11-03
------------------------------------------------------------------------

Submodels
- A submodel now has a properties dialog, based on Simile's, with four
  tabs. Instances: single, fixed array or population, with what each
  means. Styling: Relative scale, Background shade and Hide contents.
  Notes: Description and Comments. Advanced: Time step index, Use units
  in math, First index is 0 and Enumerated types.
- Relative scale changes how big a submodel's contents are drawn; the
  box and where things are in it stay as they are.
- Hide contents draws a submodel as a closed box, with arrows stopping
  at its edge.
- Comments, background shades, enumerated types and every time step
  index are now kept when a Simile model is imported and exported.
  Before, they were lost. Models imported from Simile show its shades.

Large models
- Compiling the nkometou model in the page takes about four minutes
  instead of about eight. Models are compiled exactly as before.
- Exporting it takes under two seconds instead of about nine.
- Double-clicking a submodel in a large model now opens its dialog; it
  often did nothing. A double-click on an arrow that runs over an
  element opens that element's dialog.
- Clicking an element no longer redraws the whole diagram.

Embedded-widget pages
- The sample pages (Trees, Predator-prey) start running at once again,

Release 2026-11-09
------------------------------------------------------------------------

Working safely
- Simile open in two tabs no longer loses work. Before, each tab saved
  over the other, so models made or changed in one could disappear.
  Now the tab opened last is the one that saves; any other says
  "Simile is open in another tab" and stops saving, with a button to
  use it there instead.

Opening models from the web
- A link can open a model in Simile: add ?open= and the address of the
  model's file (what File > Save writes) to Simile's address. The model
  is added to your models as a copy and opened. If a parameter file is
  beside it, its values are loaded too. Following the same link again
  offers the copy you already have. This is for a model library to come,
  but any address works.
- A page with Simile widgets embedded in it can give its model's address
  instead of the model itself (see Help > Embedded-widget pages).

Checking models
- A model whose equation uses a name that nothing supplies (no influence
  arrow brings it, or the element was deleted) is now refused when it is
  run, saying which name. Before, the run failed with only "the model
  would not compile".
- size() of a submodel, such as size(cell), is no longer drawn red: it
  needs no influence arrow. This affected several catalogue models.

Help
- The pictures in all three tutorials are retaken with Simile as it is
  now. The Trees tutorial's submodel step matches the submodel dialog,
  and submodels can be coloured, as the original tutorial does.
- Throughout, "select" instead of "choose".
