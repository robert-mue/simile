Live models in your own web pages

A guide for anyone who wants to explain a dynamic system with a model readers can run.

A model is easier to understand when you can watch it run, change it, and run it again. This guide shows how to put a Simile model into an ordinary web page of your own, among your own text: its diagram, graphs of its results, and sliders for its parameters. The model runs as soon as the page opens. Readers can move the sliders, or change the model itself, and see what happens.

It takes three files: the page, the model, and one line that brings in Simile. You do not need to install anything, run a server, or know any programming beyond copying a few lines of HTML.

For a finished example, open Rabbits and foxes and look at its source.

1. Build the model

Build and run your model in Simile on the web, as usual. The tutorials show how.

Two things are worth doing before you export it.

Give it parameters, if you want sliders

A slider can move a parameter: a variable whose value is a plain number, which nothing else in the model influences, and which has a Minimum and a Maximum (set them in the variable's properties dialog). The page gives every parameter a slider running from its minimum to its maximum.

So instead of writing a number into an equation, such as 0.2*foxes, draw it out as a variable of its own, fox_death_rate = 0.2, with an influence into the flow, and write fox_death_rate*foxes. The model means the same, and now the number has a name, a place on the diagram, and a slider.

A starting value can be a parameter too: a variable such as initial_rabbits with an influence into the stock, whose initial value is then initial_rabbits.

Set how it runs

In the run control, set Execute for and Time step(s) as you want the page to run the model. The settings go with the model when you export it.

2. Export it as a script

With the model current, choose File › Export model as script (.js)…. You get a file named after the model, such as predator-prey.js. Put it in the same folder as your page.

The file is the model, with one line round it that hands it to the page. The first lines say what to call it:

// Predator-prey — a Simile model, exported 2026-10-14.
// For a page with widgets embedded in it: load this file with
//   <script src="predator-prey.js"></script>
// and refer to the model as data-model="predator-prey" (see src/page.js).
Simile.model("predator-prey", { … }, {"runLength":50,"logEach":1,"timeStep":"0.1"});

If the model is not complete, the export refuses and says which elements need attention, as running it would.

3. Write the page

Here is a complete page. Save it as index.html beside predator-prey.js and open it in a browser.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Rabbits and foxes</title>
  <script src="https://robert-mue.github.io/simile/embed.js"></script>
</head>
<body>
  <h1>Rabbits and foxes</h1>
  <p>Your own text, as much as you like.</p>

  <div data-simile="diagram"  data-model="predator-prey"></div>
  <div data-simile="controls" data-model="predator-prey"></div>
  <div data-simile="plotter"  data-model="predator-prey" data-show="rabbits"></div>
  <div data-simile="plotter"  data-model="predator-prey" data-show="foxes"></div>
  <div data-simile="sliders"  data-model="predator-prey"></div>

  <script src="predator-prey.js"></script>
  <script>Simile.page();</script>
</body>
</html>

Three things make it work:

  1. The embed.js line in the head brings in Simile: everything needed to draw and run models, and the styles for them.
  2. An empty <div> for each thing you want to show, where you want it. data-simile says what goes there and data-model which model it shows. Everything else on the page is yours: text, pictures, headings, your own styles.
  3. At the end, the model's script and then Simile.page(), which fills in the <div>s and runs the model.

4. What you can put in a page

data-simileWhat it showsSettings
diagramThe model's diagram. Readers can zoom and pan, and double-click an element to see or change its equation.
plotterA graph of variables against time, drawn as the model runs.data-show: the variables to plot, separated by spaces. A variable in a submodel is named with its path: tree/size.
lollipopThe members of a population standing at their positions, each as tall as its size, in 3-D.data-options='{"x":"tree/x", "y":"tree/y", "size":"tree/size"}'
slidersA slider for each of the model's parameters.
controlsThe run's status, and buttons to Run again and to Reset model.

Any widget's other settings can be given as JSON in data-options. For example, a diagram shows only its zoom buttons on a page; data-options='{"tools":"all"}' gives it the whole editing palette.

Sizes

Each widget fills the box it is given, and has a sensible height of its own. To change it, give the <div> a height, in a style attribute or your own stylesheet:

<div data-simile="diagram" data-model="predator-prey" style="height: 500px"></div>

Widths follow the page. To put two graphs side by side, use your own layout, such as a CSS grid; the example page does this.

5. What your readers can do

  • Watch it. The model runs as the page opens, so the graphs are already drawn.
  • Move a slider. When they let go, the model runs again with that value. A rate takes about a second; a starting value a few, because the model is built again with it. model values puts the sliders back.
  • Change the model. Double-clicking an element of the diagram opens its equation. After an edit, the model runs again by itself.
  • Start again. Reset model undoes every change and runs the model as your page gave it.

Nothing a reader does is kept. Each visit starts with the model exactly as you exported it, and nothing is written to the reader's computer.

6. Good to know

The model runs on a server

The page draws everything itself, but the model runs on SimiLive, the Simile engine at simulistics.com. A reader needs an internet connection, and each page visit starts a run there.

One running model per page

A page can show several models' diagrams, but only one model runs: the first one the page loads. Put each model you want running on a page of its own.

The page can be anywhere

The page and the model's script are ordinary files. Open them from your own disk, or put them on any web host: a university page, a blog that accepts HTML, GitHub Pages. Nothing has to be set up on the host.

Using your own copy of Simile

embed.js loads everything else from wherever it was itself loaded from. If you have a copy of Simile on the web, or on your disk, point the <script> at that copy's embed.js instead, and nothing else changes. The example page does this, with ../../embed.js.

Changing the model later

Edit it in Simile on the web, export it again, and replace the .js file beside your page. The page itself does not change.
